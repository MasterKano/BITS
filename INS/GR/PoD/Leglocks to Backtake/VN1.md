# VIEWING NOTES – Gordon Ryan: Pillars of Defense — Leg Locks to Back Takes

## 1.0 Volume 1 — Foundations + Intro to Irimi Ashi

### 1.1 Intro
**Key concepts**
- Convert leg entanglements into upper-body positional gains (back takes / guard passes), not “leg attacks as a separate game.”
- Sequencing focus: link threats so defense to one outcome feeds the other (back ↔ pass).
- “Defense first, then offense” framing for each ashi family (solve safety/constraints before chasing conversions).

**Position–structure**
- Start state: leg entanglement / leg attack context.
- Finish states: upper-body control lanes (upper-back connection for back takes; cranial control for pins/passes).

**Decision rules (IF/THEN)**
- IF back exposure is denied or slipping -> THEN convert immediately into a passing/pinning lane (no reset).
- IF passing pressure triggers turn-away -> THEN treat that as your back-opening reaction and attach.
- IF a constraint is active (heel/achilles access against you) -> THEN solve constraint before large transitions (stand/roll/commit).

**Failure signatures + fixes**
- You “win the legs” but stall (no control/attack) -> shift to cranial control (head/shoulders) immediately.
- You chase a backtake with distance/gaps -> stop hook-chasing; rebuild upper-body connection first.

**Completion checks**
- Back: chest-to-upper-back connection + centre lines aligned (not just “lower-back exposure”).
- Pass: head/shoulder control achieved (cranial shift) with stable pin pressure.

**System tags**
- Conversion loop; Pass/back dilemma; Defense-first gates; Cranial shift; Upper-back standard

### 1.2 Overview
**Key concepts**
- Macro structure mirrors “leg locks → guard passes” logic: backtake attempts feed passing; passing feeds back openings.
- Volume ordering emphasis: Irimi ashi first, then Outside ashi (defense-first, then offense).
- Core promise: systematic conversion from leg attacks into (a) back takes, (b) passes, with predictable branches.

**Position–structure**
- Irimi and Outside ashi used as primary “conversion hubs” before expanding to other ashi families.

**Decision rules (IF/THEN)**
- IF you can’t secure the back cleanly -> THEN you should land in a pass lane.
- IF you can’t keep a pass lane stable -> THEN anticipate turn reactions and use them to re-open back attachment.
- IF you’re still solving foot/achilles safety -> THEN do not progress to high-amplitude transitions.

**Failure signatures + fixes**
- You treat each chapter as isolated techniques -> reframe as one loop with branch triggers (turn toward / turn away / invert).
- You switch hubs too early (before safety is solved) -> return to defense-first work until transitions are safe.

**Completion checks**
- You can name the branch trigger and its lane (what reaction selects pass vs back) before executing.
- You can exit the leg exchange into a stable top lane on command (pin/pass or back-attach).

**System tags**
- Curriculum spine; Irimi hub; Outside hub; Branch triggers; Safety-first

### 1.3 Theory
**Key concepts**
- Dilemma principle: single threats are easy to defend; layered threats expand the defensive “coverage problem.”
- Soccer-net analogy: the wider the goal, the harder it is to cover; multiple threats widen the “net.”
- Winning comes from forcing defense choices that expose the next threat (attack domain switching).

**Position–structure**
- Threat layering across domains: lower-body threats force reactions that expose upper-body outcomes.

**Decision rules (IF/THEN)**
- IF partner can defend by addressing one line with one structure -> THEN you need a second, linked threat.
- IF defense is committed to leg safety -> THEN climb to upper-body connection (back/pin).
- IF defense is committed to upper-body prevention (turn-in) -> THEN accept pin/passing advancement.

**Failure signatures + fixes**
- You keep re-attacking the same threat into a settled defense -> switch domains (legs → upper-body control).
- You “create exposure” but don’t convert -> add completion criteria (upper-back connection + cranial control).

**Completion checks**
- You can state the paired threats you are presenting and what defense to A opens for B.
- You can identify the defender’s choice (turn toward/away) and branch without hesitation.

**System tags**
- Dilemma model; Threat layering; Domain switching; Reaction-led branching

### 1.4 Cranial shift
**Key concepts**
- Being “past the legs” is not sufficient; you must control head/shoulders to attack and stabilize.
- Example: body-lock pass can be “technically passed,” but without cranial shift you cannot progress/attack.
- Cranial shift is the bridge that turns leg wins into stable pins/passes (and sets up the pass/back dilemma).

**Position–structure**
- Transition gate: leg clearance / positional advantage -> cranial control (head/shoulders) -> stable pin/attack platform.

**Decision rules (IF/THEN)**
- IF you are past the legs but cannot attack -> THEN you have not completed cranial shift; move to head/shoulder control now.
- IF the partner is turning to deny one lane -> THEN use cranial control to keep them pinned while you take the other lane.
- IF you lose head/shoulder control -> THEN expect re-guarding/re-square and re-establish cranial control before advancing.

**Failure signatures + fixes**
- “Scored” but no attacks available -> re-orient to upper-body controls and re-pin.
- You chase movement without head control -> slow down and secure cranial shift first.

**Completion checks**
- Pin/passing lane: head/shoulder control established such that partner can’t freely turn/insert frames.
- You can progress without needing “speed scrambling” because control exists.

**System tags**
- Cranial shift; Head/shoulder control gate; Pin stabilization; Pass/back platform

### 1.5 Upper vs lower back exposure
**Key concepts**
- Backtake completion targets upper back, not just lower-back exposure.
- Completion standard: chest-to-upper-back connection + centre lines aligned.
- No-gi adaptation: you cannot rely on belt grips; you must use modified upper-body grips (trap / cross-trap variants) to connect and align.
- Practical implication: build connection first; hook pursuit is downstream.

**Position–structure**
- Exposure ladder: create upper-back exposure -> connect chest-to-upper-back -> align centre lines -> insert hooks/finish.

**Decision rules (IF/THEN)**
- IF you only have lower-back exposure -> THEN treat it as incomplete; upgrade to upper-back connection before finishing.
- IF you cannot maintain connection with pull-only grips -> THEN use the pushing-capable connection (cross-trap) to keep them pinned/returned.
- IF centre lines are not aligned -> THEN don’t rush hooks; fix alignment through connection and pressure first.

**Failure signatures + fixes**
- Hooks are attempted while chest-to-upper-back connection is weak -> stop hook-chasing; rebuild connection with trap/cross-trap.
- Partner’s back returns to the mat during the transition -> re-apply the connection that allows you to drive/push them back down.

**Completion checks**
- Upper-back connected to your chest; centre lines aligned.
- You can maintain the exposure through the transition (not a momentary “flash exposure”).

**System tags**
- Upper-back standard; Connection-before-hooks; Centre-line alignment; Trap/cross-trap grips

### 1.6 Hips and knees
**Key concepts**
- Backtake reliability diagnostic: “partner’s hips inside my knees” = back is available.
- If hips drift outside your knees, the back take degrades (you’re losing the corridor that contains their pelvis).
- Two-goal completion model for back takes:
  - upper-body: chest-to-upper-back + centre lines aligned
  - lower-body: hips contained between your knees

**Position–structure**
- Knee corridor contains the hips while you build and maintain the upper-back connection.

**Decision rules (IF/THEN)**
- IF hips are inside your knees -> THEN continue backtake completion.
- IF hips begin drifting outside your knees -> THEN immediately adjust containment or switch to a safer lane (pin/pass).
- IF you can’t maintain both goals (upper-back + hip containment) -> THEN treat the back as failing and branch.

**Failure signatures + fixes**
- You feel them “scoot out and away” (hips escaping your knees) -> prioritize hip containment before hook insertion.
- You maintain upper-body connection but lose hips -> use your legs/knees to re-capture the hip corridor or abandon to pass.

**Completion checks**
- Hips remain between your knees during the finish sequence.
- Upper-back connection is maintained while containment is preserved.

**System tags**
- Hips-inside-knees diagnostic; Hip containment; Backtake completion criteria; Corridor control

### 1.7 Rule of the Achilles
**Key concepts**
- Achilles grip is described as the defender’s “saving grace” against backtakes from leg exchanges.
- Achilles control functions as a constraint gate: when active, backtakes become dramatically harder.
- General rule stated: Achilles grip presence/absence meaningfully changes the decision tree.

**Position–structure**
- Constraint layer applied while you attempt to convert from legs to back/passing.

**Decision rules (IF/THEN)**
- IF partner has an effective Achilles grip -> THEN treat back chase as constrained; clear/deny it or change lane.
- IF partner does not have an effective Achilles grip -> THEN backtake options open (chase becomes more realistic).
- IF you ignore Achilles control while transitioning -> THEN expect heel/foot exposure and defensive recovery.

**Failure signatures + fixes**
- You attempt to chase the back while Achilles grip is present -> switch: address the grip/constraint first or convert to passing.
- You stand/roll while Achilles control is active -> re-solve foot safety and constraint before reattempting the transition.

**Completion checks**
- Achilles constraint is neutralized or no longer functionally limiting before committing to a backtake pathway.
- Your transition does not expose heel/foot to immediate attacks.

**System tags**
- Achilles constraint; Gate rule; Constraint-first branching; Transition safety

### 1.8 Intro to Irimi Ashi — Hiding your foot
**Key concepts**
- Defensive dilemma described: Achilles lock vs heel hook threats demand different foot orientations.
- “Booting” the foot makes Achilles locking harder; heel-hook defense requires controlling heel exposure.
- Foot distance principle: the closer your foot is to the opponent’s body, the easier it is for them to attack.

**Position–structure**
- Irimi defensive base: manage foot/heel safety first so you can extract and convert upward.

**Decision rules (IF/THEN)**
- IF opponent’s primary attack is Achilles lock/control -> THEN boot the foot to reduce their ability to lock/extend.
- IF opponent transitions toward heel hooks -> THEN prioritize heel hiding (avoid presenting the heel line).
- IF your foot is drifting closer to their body -> THEN correct distance/orientation before attempting to stand/extract.

**Failure signatures + fixes**
- You “boot” to stop Achilles but start exposing heel line -> switch orientation to hide heel and remove heel-hook access.
- Opponent gains purchase as your foot closes distance -> re-position foot away from their body and re-solve the dilemma.

**Completion checks**
- Your foot orientation denies the current primary threat (Achilles or heel hook) without giving the other for free.
- You can maintain safety while beginning extraction/movement.

**System tags**
- Irimi foot safety; Achilles vs heel-hook dilemma; Booting; Heel hiding; Foot-distance management

### 1.9 Intro to Irimi Ashi — Basic recap
**Key concepts**
- Recap emphasizes extraction mechanics and immediate conversion up the body.
- Extraction is paired with reaction reading: opponent coming forward / turning creates back exposure opportunities; squaring/turning in supports pass lanes.
- Emphasis on controlling the foot/ankle line while you “scoot/step/sit” to create the extraction.

**Position–structure**
- Irimi -> extraction movement (scoot/step/sit over the foot) -> conversion phase (come up as partner reacts).

**Decision rules (IF/THEN)**
- IF you can extract cleanly -> THEN come up into upper-body control immediately (don’t remain in leg-only space).
- IF opponent comes forward into you during extraction -> THEN use that to close distance into your conversion (come up/attach).
- IF opponent turns away as you come up -> THEN attach to back; IF they turn toward -> accept chest-to-chest lane and pass.

**Failure signatures + fixes**
- Extraction creates space but you don’t connect -> close distance with upper-body control immediately (cranial shift principle).
- Opponent reattacks your heel during sloppy movement -> slow down, re-solve foot safety, then continue extraction.

**Completion checks**
- Leg is extracted without exposing heel line.
- You finish the sequence in an upper-body lane (back attachment or pin/passing base), not neutral.

**System tags**
- Irimi extraction; Reaction reading; Conversion timing; Cranial shift follow-through

### 1.10 Hip-fall backtakes vs inversion-based responses
**Key concepts**
- Common defensive recovery: when they lose the leg, many opponents elect to invert to recover.
- Early inversion rule: pin an ankle immediately; “as soon as you see inversion,” pin ankles before full inversion forms.
- Hip control + knee placement used to prevent the partner threading legs back inside while you convert.
- Upper-body connection options emphasized during the fall-to-hip completion: hip + trap / cross-trap connections to pull them into your lap and connect upper back to your chest.
- Back-head-and-arm capture appears as a stabilizing moment during completion; head positioning must be maintained.

**Position–structure**
- Inversion branch: inversion starts -> ankle(s) pinned -> hip controlled -> knee placed to block re-entry -> fall to hip -> connect upper back to chest -> back-head-and-arm -> insert hook(s) -> finish.
- Alternative framing: use inversion as an opportunity to extract and climb rather than “fighting the inversion late.”

**Decision rules (IF/THEN)**
- IF you see inversion begin -> THEN pin an ankle immediately (before full inversion).
- IF ankles are pinned -> THEN control hip and place knee to prevent their legs re-threading inside.
- IF you can connect upper back to your chest via hip+trap / cross-trap during the fall -> THEN proceed to back-head-and-arm and hook insertion.
- IF head position is degrading during the come-up -> THEN fix head position before advancing (prevents them scooting out/escaping).

**Failure signatures + fixes**
- You wait until full inversion -> ankles become hard to control -> pin earlier (timing correction).
- Partner scoots hips out and away during completion -> maintain head position and contain hips (return to “hips inside knees” goal).
- Connection feels pull-only and slips when you need to drive them back -> switch to the connection that allows you to push/drive (cross-trap emphasis).

**Completion checks**
- Ankles pinned early enough that inversion never fully forms.
- Upper back is connected to your chest during the fall-to-hip phase.
- You can insert a top hook while maintaining hip containment and head position.

**System tags**
- Inversion timing; Ankle pin; Hip control; Fall-to-hip finish; Trap/cross-trap; Back-head-and-arm; Head position gate

### 1.11 Failed backtake -> tight waist guard pass
**Key concepts**
- Explicit failure branch: if you cannot create/keep upper-back exposure, switch to tight waist rather than forcing a degrading back chase.
- Stand-up/build sequence is governed by a continuous knee–elbow connection to deny the knee-through recovery.
- Shallow vs deep tight waist both acceptable; the invariant is knee–elbow connection during the heist to the knee.
- Two stated defensive “saves” if knee–elbow separates:
  - reconnect knee and elbow directly
  - or shelf configuration to reconnect and block hip movement (denies shrimp-out)

**Position–structure**
- Backtake attempt fails (upper-back exposure lost) -> tight waist -> build to elbow -> heist to knee -> stabilize top lane -> pass “on your terms.”

**Decision rules (IF/THEN)**
- IF you can’t keep upper-back exposure -> THEN switch to tight waist immediately.
- IF you start building up -> THEN maintain knee–elbow connection the entire time.
- IF knee–elbow separates and their knee begins coming through -> THEN reconnect via direct clamp OR shelf variation before they invert/escape.
- IF you stabilize the tight waist and deny shrimp -> THEN post and rise into top passing structure.

**Failure signatures + fixes**
- Upper-back exposure collapses mid-finish -> tight waist switch (no hesitation).
- Knee starts threading through space during your rise -> re-connect knee–elbow immediately (direct or shelf).
- They attempt to shrimp out and away during your build -> shelf connection to block the hip and remove shrimping ability.

**Completion checks**
- Tight waist established with knee–elbow connected before you commit height.
- You reach a stable top position where they “have no shrimping ability” and you can pass on your terms.

**System tags**
- Tight waist anchor; Knee–elbow connection; Failure-branch conversion; Heist to knee; Anti-knee-through; Shrimp denial
