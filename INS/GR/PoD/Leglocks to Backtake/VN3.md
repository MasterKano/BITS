# VIEWING NOTES – Gordon Ryan: Pillars of Defense — Leg Locks to Back Takes

## 3.0 Volume 3 — Intro to Butterfly Ashi

### 3.1 Intro to Butterfly Ashi
**Key concepts**
- Butterfly ashi is introduced as another conversion hub: same objective (back takes / passes), same reaction-based lane selection.
- Hub mindset: do not “live” in the entanglement; use it to force reactions and climb to upper-body control.
- Structural priority: maintain your own foot/heel safety while converting (no self-exposure during the climb).

**Position–structure**
- Start state: butterfly ashi entanglement (stable enough to create conversion timing).
- Transition: come-up (knee/standing) into upper-body lanes (underhook/body-lock style control).
- Finish states: chest-to-chest pin (pass lane) or chest-to-upper-back attachment (back lane).

**Decision rules (IF/THEN)**
- IF butterfly ashi is stable and safety is intact -> THEN begin the come-up toward top control (don’t stall).
- IF the defender turns away under pressure -> THEN attach to upper back (back lane).
- IF the defender turns toward to deny attachment -> THEN accept chest-to-chest and commit to passing.
- IF safety degrades (heel/foot exposure) -> THEN re-solve safety before committing to height/rotation.

**Failure signatures + fixes**
- You come up and they re-square/re-enter legs -> fix by maintaining lower-body control until upper-body connection is established.
- You chase a backtake without upper-back connection -> fix by building chest-to-upper-back first, then pursue hooks.

**Completion checks**
- You exit butterfly ashi into a control lane (pin/attachment), not neutral space.
- Lane choice is determined by reaction and is immediate (no “in between”).

**System tags**
- Butterfly ashi hub; Conversion loop; Reaction-led branching; Safety-first gate; Lane commitment

### 3.2 Build to standing
**Key concepts**
- Standing is treated as a completion tool when grounded progress stalls: convert leg control into top control via height.
- Standing is a means to secure upper-body lanes while denying the defender time to rebuild/re-square.

**Position–structure**
- Butterfly ashi -> momentum/angle -> build to knee -> rise to standing -> establish upper-body connection (underhook/body-lock type).

**Decision rules (IF/THEN)**
- IF grounded progress stalls but control exists -> THEN build to standing (use height to finish conversion).
- IF standing creates separation -> THEN close distance immediately with upper-body connection (don’t float).
- IF safety is threatened during the rise -> THEN stop and re-solve (don’t continue rising into exposure).

**Failure signatures + fixes**
- You stand and lose connection -> fix by treating the stand-up as a bridge: lower-body control stays until upper-body control is in.
- You reach standing but have no pin/attachment -> fix by connecting immediately into your chosen lane before advancing.

**Completion checks**
- Standing ends with a real upper-body lane established (pin/attachment), not just “being up.”
- Defender cannot freely re-square during/after the rise.

**System tags**
- Come-up milestone; Stand-to-convert; Connection timing; Safety management

### 3.3 Passing and backtake options
**Key concepts**
- Explicit two-lane model from butterfly ashi conversions:
  - turn-toward / deny back -> pass lane
  - turn-away / flee pressure -> back lane
- “Acceptable landing” principle: ending chest-to-chest in a half-guard-ish top situation is acceptable if it is stable and feeds passing.

**Position–structure**
- Butterfly ashi -> convert upward -> either chest-to-chest pin (pass) or chest-to-upper-back attachment (back).

**Decision rules (IF/THEN)**
- IF defender turns toward -> THEN pin chest-to-chest and progress the pass (don’t insist on hooks).
- IF defender turns away -> THEN attach chest-to-upper-back before hook pursuit.
- IF you are not in a lane (neither pin nor attachment) -> THEN stabilize first (choose the lane) before finishing.

**Failure signatures + fixes**
- You hover between pass/back and get scrambled -> fix by committing to a lane immediately after the reaction.
- You chase hooks while turn-toward is present -> fix by accepting chest-to-chest and passing.

**Completion checks**
- Pass lane: stable chest-to-chest pressure with measurable passing progress.
- Back lane: upper-back connection + centre-line alignment before hooks.

**System tags**
- Pass/back dilemma; Lane commitment; Acceptable landings; Connection-before-hooks

### 3.4 Intro to Irimi Ashi offense (from butterfly ashi context)
**Key concepts**
- Configuration transfer: butterfly ashi can be used to transition into irimi ashi offense to keep the system moving.
- Goal is continuation: when one configuration stalls, move to the hub that reopens conversion routes.

**Position–structure**
- Butterfly ashi -> transfer to irimi ashi -> apply irimi conversion families + fail-safe branches.

**Decision rules (IF/THEN)**
- IF butterfly ashi stalls (no clean lane) -> THEN transfer to irimi ashi to restart your strongest conversion pathway.
- IF transfer creates a safety issue -> THEN re-solve safety before committing to rotation/come-ups.
- IF irimi creates a cleaner reaction set -> THEN branch immediately (turn away = back, turn toward = pass).

**Failure signatures + fixes**
- You grind a stalled configuration -> fix by transferring configurations rather than forcing progress.
- Transfer is loose and creates scramble -> fix by maintaining control through the transition, then re-enter the lane.

**Completion checks**
- Transfer produces a clearer lane (pin/attachment) than the stalled position.
- You can branch quickly after transfer based on reaction.

**System tags**
- Configuration transfer; Irimi re-entry; Continuation principle; Safety-first

### 3.5 Underhooks to backtake
**Key concepts**
- Underhook is presented as the primary bridge from butterfly ashi into upper-body control.
- Underhook supports the dilemma: it either pins (turn-toward) or opens attachment (turn-away).

**Position–structure**
- Butterfly ashi -> secure underhook -> climb to top/connection -> branch (pin/pass vs back attach).

**Decision rules (IF/THEN)**
- IF you secure an underhook with posture -> THEN climb into chest-to-chest or chest-to-back depending on reaction.
- IF defender turns away under underhook pressure -> THEN attach to upper back (connection first).
- IF defender turns toward or frames to deny attachment -> THEN accept chest-to-chest pin and pass.

**Failure signatures + fixes**
- Underhook is loose and they square -> fix by pairing underhook with head/torso alignment (don’t treat it as “arm only”).
- Underhook becomes a pummel/frame battle -> fix by stabilizing in a pin lane before re-advancing.

**Completion checks**
- Underhook produces a real control lane (pin/attachment), not a neutral clinch.
- You can prevent immediate squaring long enough to finish branch.

**System tags**
- Underhook bridge; Upper-body control gate; Reaction-led branching; Pin-first conversion

### 3.6 Heel hook to backtake
**Key concepts**
- Heel hook threat is used as leverage: defensive commitment (hands/turns) creates conversion windows.
- Objective is reaction capture: threat forces a predictable response that opens either back or pass.

**Position–structure**
- Butterfly ashi -> present heel threat -> defender commits defense -> attacker climbs to upper-body lane.

**Decision rules (IF/THEN)**
- IF defender commits hands to heel defense -> THEN climb up the body (conversion timing).
- IF defense causes turn-away -> THEN attach to upper back.
- IF defense causes turn-toward / squaring -> THEN accept pin lane and pass.

**Failure signatures + fixes**
- You over-invest in the heel threat and miss the climb window -> fix by treating the threat as a trigger, not the goal.
- You climb without safety -> fix by ensuring your own foot/heel is protected before committing upward.

**Completion checks**
- The threat produces a conversion (pin/attachment), not a prolonged leg hand-fight.
- You exit in a stable top lane or back attachment.

**System tags**
- Threat-as-leverage; Reaction capture; Conversion timing; Safety-first

### 3.7 Butterfly ashi offense (hub consolidation)
**Key concepts**
- Consolidation chapter ties together:
  - come-ups (knee/standing),
  - underhook bridge,
  - heel-threat leverage,
  - and reaction-led lane selection.
- Butterfly ashi is treated as a repeatable platform to start the conversion engine when other hubs aren’t present.

**Position–structure**
- Start in butterfly ashi -> upgrade to pin/attachment -> finish as pass or back; transfer hubs if stalled.

**Decision rules (IF/THEN)**
- IF you can convert immediately -> THEN choose lane by reaction (toward = pass; away = back).
- IF you can’t stabilize a lane -> THEN use a stabilizer step (pin first) before finishing.
- IF hub stalls -> THEN transfer to another configuration (e.g., irimi) that reopens conversion routes.

**Failure signatures + fixes**
- Treating hub as a place to stay -> fix by enforcing “exit with structure” (lane commitment).
- Coming up without connection -> fix by maintaining lower-body control until upper-body lane is secured.

**Completion checks**
- You can reliably exit butterfly ashi into either a stable pin/pass or stable back attachment.
- Branching is immediate and repeatable under resistance.

**System tags**
- Hub system; Structured exits; Lane commitment; Dilemma loop enforcement; Transfer option
