# Strategy — Constant Threat (Legs as the Target They Can’t Hide)

## 1. Purpose
A strategic doctrine for open guard: create a constant, credible threat that changes opponent behavior. In this instructional, leg access is treated as the most posture-proof threat.

## 2. Core Claim (behavior shaping)
Opponent behavior is governed by belief:
- if passing feels low-risk, they pass aggressively and repeatedly;
- if passing feels costly, they hesitate, commit slower, and expose more predictable reactions.

## 3. Why legs are prioritized
Legs are treated as the “target they can’t hide”:
- standing, kneeling, or staggered, the legs remain available for attachment and off-balancing;
- posture alone cannot remove legs from the engagement the way it can with head/arms.

Operational implication:
- open guard retention is improved when the opponent must constantly respect leg entries.

## 4. Implementation (what “constant threat” means in practice)
Constant threat is not intent; it is repeated, structurally valid attempts that satisfy the system gates:

- **Connect:** secure a true handle (often ankle/heel line) before climbing.
- **Break base:** earn hands-down / posting / widened stance.
- **Enter:** choose the simplest entry family that matches range and posture.
- **Stabilize:** land in a hub that prevents the easy reset (containment vs barrier vs backside stability).

If you skip validity (hands-down) or connection redundancy, the threat is not credible and does not change behavior.

## 5. Common tools used to project the threat (distance-to-attachment)
- 2-on-1 ankle concepts (attach to the “knot” before climbing)
- partial inversion distance breakers (connect from outside range)
- shin-to-shin as a connector (lift/steer into leg engagement)

(These are implemented as separate entry modules; this file governs the strategy.)

## 6. Failure Signatures
- “He just keeps passing” → threat not credible (no base break, no attachment, no hub)
- “He steps away every time” → anti-exit governance missing; attachment is thin
- “I enter and lose it instantly” → no true handle; wedge/space not occupied
- “I get smashed when I try” → hands-down gate violated (stable base)
