# Retention Model — Knowledge/Denial (Open Guard)

## 1. Purpose
A retention method that defends **requirements**, not named passes. The practitioner identifies what the passer must accomplish next, denies a single requirement, and re-centers before the next requirement is built.

## 2. Core Principle
- Passing succeeds by completing a required build sequence.
- Retention succeeds by denying **any one link** in that sequence early enough that the pass cannot progress.

This model prevents late-stage survival habits (defending only once penetration/pin is already forming).

## 3. Operational Loop
1) **Diagnose:** what requirement is being built right now?  
2) **Deny:** break that requirement decisively.  
3) **Re-center:** restore alignment + barriers.  
4) **Convert:** on cycle break, initiate counter-offense (do not pause).

## 4. Denial Targets (how denial is expressed)
Denial is executed through:
- **Distance control:** keep hips safe; keep frames/legs between bodies.
- **Grip disruption:** prevent stable connections that allow level/angle.
- **Angle denial:** keep opponent in front; re-square; prevent outside knee line.
- **Level denial:** prevent chest-to-chest compression and underhooks/locks.
- **Penetration denial:** stop the passer from getting past your knee line / hip line.
- **Pin denial:** prevent shoulder/hip immobilization that ends guard work.

(Exact “six elements” are defined in the companion file.)

## 5. Gates (what forces escalation)
### 5.1 Hip Line Gate (escalation trigger)
- In front of hip line: movement solutions dominate.
- At/past hip line: defensive cycle; frames + re-alignment are mandatory.

### 5.2 Orientation Rule (retention integrity)
- feet or knees must face opponent continuously.
- loss of both = rapid angle and hip line loss.

## 6. Validation Tests (is denial working?)
Denial is working if one of these is true:
- opponent is re-centered (cannot keep angle)
- opponent must reset grips/stance
- opponent is forced to post or widen base
- penetration stalls before pinning begins

If none occur, denial was late or targeted the wrong requirement.

## 7. Failure Signatures
- **“I defended the pass but he kept going”** → denial too late (target was pin, not earlier link)
- **“He got the angle easily”** → orientation rule violated; re-square failure
- **“He smashed through my spin”** → hands-down gate violated (entered without base break)
- **“He keeps resetting freely”** → anti-exit governance missing; connection not redundant
